## Review fixes on this branch (27 October, Harsh)

Added after reviewing PR #5 against the plan; each fix has its own commit, and each test was seen failing before its fix. Aaryan's text above is kept as written except the resolved limitation.

- **Planner (A06):** rows no longer keep the previous revision's eligibility and issues after an unsaved or failed edit; they show "Not checked" until the server validates. Current term and a new plan's first term use the latest *completed* term, so an in-progress semester is not skipped.
- **Drafts (A02/A04):** a per-tab registry keeps unsaved plan and enrolment drafts across navigation and session expiry for the same account, sends a draft immediately when its view closes, warns before closing the tab, and drops drafts on sign-out or account switch. The expiry banner now says exactly that.
- **Errors (A02):** "Try again" after an analysis 409 reloads the record first (it used to conflict forever); non-JSON error pages keep their status, so a malformed plan link shows "Plan not found".
- **Record (A04):** "Academic history" marks credits of failed/in-progress attempts as not earned; the correction dialog keeps an unknown status and states that a code change is not an equivalence; code/credit checks in every form mirror the server rules (`frontend/src/lib/validation.ts`).
- **Shell/performance (A01/A07):** the data context no longer resets to "—" when going from a public page to a protected one, and shows the rule review status everywhere; missing points/denominators read "Unavailable".
- **Contract (requests 6, 7 and a new drift):** schema and examples match the real server for plan-validation `workload` (keyed by term), the audit's always-present fields and the record's `current_enrolment`/`reported_controls`. `frontend/src/test/contract.test.tsx` renders the shared `examples/*.json`, and the Django schema test now also validates a real plan-validation response. `schemas/statement-test-map.json` maps frontend and browser tests to CP IDs, checked by `tests/domain/test_statement_map.py`.
- **Test honesty (A10):** the browser CPI check requires "Unavailable" plus 132 points over 18 credits (computed by hand from `IMS_TEXT`), the audit step checks that CS 203 does not satisfy CS 202, the sign-out check runs in the same tab, and the fake plan server's totals differ from a naive client sum.
