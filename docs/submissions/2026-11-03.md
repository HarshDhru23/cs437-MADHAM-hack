Manashree found a frontend race: `frontend/src/features/plan/timetable.test.tsx:297` (from #29) failed in 2 of 4 runs through `scripts/test.py` and passed alone.

- **Observed:** the "why not checked" note was read while it still said "The server has not validated this plan yet".
- **Cause:** the assertion did not wait for the validation response. Two more assertions in the same file (button labels that change once validation arrives) had the same race.
- **Fix (Harsh, in this PR):** all three now wait for the server's text with `waitFor`; no expected value changed. The full Vitest suite then passed 5 of 5 runs with 8 workers. Aaryan, as the file's owner, should confirm.

The CP-32 frontend column had shown "not run" because the map listed an `it.each` title template (`a %i %s refusal ...`) instead of its two real test names; the map now lists both.

`scripts/test.py` itself crashed while printing that failure into a cp1252 log. It is fixed on this branch, with a test.

The private-input checks pass: the transcript and IMS rows match the local hand-transcribed oracle.
